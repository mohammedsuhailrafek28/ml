# Medical AI Suite

An educational, **non-diagnostic** multi-disease machine-learning demonstrator. It
estimates *risk patterns* in five public research datasets and exposes them
through a FastAPI service and a Next.js frontend. It does **not** diagnose, and it
makes **no claim of clinical validation**. Always consult a qualified healthcare
professional.

## Disease modules

| Module | Dataset | Model | Honest headline performance |
| --- | --- | --- | --- |
| Liver | UCI Indian Liver Patient (ILPD), 570 rows | Logistic Regression | holdout ROC-AUC ≈ 0.80 |
| Heart | UCI Cleveland Heart Disease, 303 rows | Logistic Regression | holdout ROC-AUC ≈ 0.97 |
| Diabetes | Pima Indians Diabetes, 768 rows | Logistic Regression | CV ROC-AUC ≈ 0.85 |
| Kidney | UCI Chronic Kidney Disease, 400 rows | Logistic Regression (14-feature) | CV ROC-AUC ≈ 1.0 — see note |
| Parkinson's | UCI Parkinson's voice, 195 recordings / 32 subjects | Logistic Regression (15-feature) | subject-aware CV ROC-AUC ≈ 0.78 — see note |

Every metric above is generated by the dedicated trainers and recorded in
`models/<disease>/metadata.json` and `reports/final_results_summary.*`.

### Kidney — near-separable dataset note
The UCI CKD dataset is close to linearly separable on legitimate clinical markers
(haemoglobin, serum creatinine, specific gravity, albumin, PCV), and every
"positive finding" categorical occurs only in CKD rows. Held-out scores near 1.0
reflect **this small curated 2015 teaching dataset**, not clinical-grade CKD
detection. The trainer records a full `perfect_score_investigation` (no target
leakage, no duplicate leakage, no preprocessing leakage; a documented
missing-data collection artefact). The model still makes 1 error on the 80-row
holdout.

### Parkinson's — subject-aware note
The dataset has ~6 voice recordings per person. Splitting at the recording level
leaks a subject across train/test: a plain probe scores **ROC-AUC 0.92 naively vs
0.57 subject-aware** on the same data. This suite uses `GroupShuffleSplit` +
`StratifiedGroupKFold` with `groups=subject` for **all** splitting, tuning and
selection. The honest figure is subject-aware CV ≈ 0.78; the ~7-subject holdout
is too small for a reliable point estimate. Inputs are **pre-computed voice
biomarkers** (from voice-analysis software) — there is **no raw-audio extraction**
in this system.

## Architecture

```
datasets/raw/*.csv
  -> src/training/train_<disease>.py   (dedicated, leakage-safe / subject-aware trainer)
       -> models/<disease>/            persisted joblib pipeline + metadata.json + metrics.json
  -> src/api/                          FastAPI: validation, inference, health/readiness, PDF report
       -> frontend/                    Next.js App Router: one assessment flow per disease
```

- `src/api/main.py` — routes + middleware wiring.
- `src/api/settings.py` — environment-driven runtime config (no new deps).
- `src/api/middleware.py` — request IDs, structured logging (no payloads), body-size limit, in-memory rate guard, security headers, shared error envelope.
- `src/api/health.py` — liveness + readiness + model-artifact integrity.
- `src/api/services/model_registry.py` — loads persisted pipelines; per-disease input validation; the **only** inference layer.
- `src/preprocessing/<disease>_schema.py` — per-disease feature semantics (single source of truth for training + API + tests).
- `src/training/train_all.py` — thin dispatcher to the five dedicated trainers.
- `app.py` — **legacy** Streamlit demo (fallback only; not the production surface).

## ML methodology (all five)

- Raw data validated + cleaned inside a scikit-learn `Pipeline` (imputation/scaling/encoding fit on training folds only — never globally).
- Stratified (or subject-disjoint, for Parkinson's) **DEV / untouched HOLDOUT** split.
- Model + hyper-parameters chosen on **DEV cross-validation ROC-AUC only**, never the holdout; simplest family within a small tie band wins.
- Operating threshold fixed at 0.5; a DEV out-of-fold sweep is published, not tuned.
- Holdout touched exactly once; permutation importance computed on the holdout.
- Old-vs-new comparison, limitations and a disclaimer recorded in metadata.
- Kidney and Parkinson's also run a fold-safe feature-selection experiment and multi-seed stability analysis.

## Requirements

- Python 3.11, Node 20.19 or newer. The frontend uses Next.js 16 and React 19.
- `requirements.txt` — API runtime (pandas, numpy, scikit-learn, scipy, joblib, reportlab, fastapi, uvicorn).
- `requirements-dev.txt` — adds pytest, httpx, matplotlib, ruff, and the optional legacy/notebook stack (streamlit, jupyter, seaborn, plotly, shap).

## Local backend

```bash
python -m venv .venv
.venv\Scripts\activate                 # Windows  (source .venv/bin/activate on Unix)
pip install -r requirements-dev.txt
copy .env.example .env                  # optional local overrides
python -m src.training.train_all        # (re)generate models/  — optional, artifacts are committed
python -m uvicorn src.api.main:app --reload
```

API: `GET /api/v1/health` (liveness), `GET /api/v1/ready` (readiness, 503 when a
model fails integrity), `GET /api/v1/diseases`, `GET /api/v1/diseases/{disease}`,
`POST /api/v1/predictions/{disease}`, `POST /api/v1/reports/{disease}`.

## Local frontend

```bash
cd frontend
npm ci
copy .env.example .env.local            # optional; defaults to http://localhost:8000
npm run dev                             # http://localhost:3000
```

## Environment variables

Backend (`.env`, see `.env.example`): `APP_ENV`, `ALLOWED_ORIGINS` (required in
production; never wildcard), `API_HOST`, `API_PORT`, `API_KEY` (blank = open demo
mode; when set, send `X-API-Key`), `MAX_REQUEST_BYTES`, `RATE_LIMIT_PER_MINUTE`,
`MODEL_ROOT`, `REPORT_DIR`, `LOG_LEVEL`.

Frontend (`.env.local`): `NEXT_PUBLIC_API_BASE_URL` (browser-exposed; no secrets).

## Training & testing

```bash
python -m src.training.train_all [--disease heart]   # dispatcher -> dedicated trainer
pytest -q                                            # full suite
ruff check --select E9,F63,F7,F82,F401,F811 src tests

npm audit --omit=dev

```

## CI

`.github/workflows/ci.yml` runs on push/PR: **backend** (deps, ruff error subset,
import smoke, pytest), **frontend** (`npm ci`, production dependency audit,
typecheck, ESLint, production build), **smoke** (start the API, hit
health/readiness, one prediction per disease, one PDF). No secrets required.

## Deployment

`Dockerfile` (backend, non-root, stdlib healthcheck), `frontend/Dockerfile`
(multi-stage, non-root), `docker-compose.yml` for a local full stack:

```bash
copy .env.example .env
docker compose up --build       # api :8000, web :3000
```

The images are provided for reproducibility; they have not been build-verified in
the development environment used to author this repo (no Docker available there).

## Production caveats

- Datasets are small, single-cohort teaching datasets from the 1980s–2010s. Metrics are not clinical validation and will not transfer to real screening populations.
- Kidney's ~1.0 and Parkinson's small holdout are dataset artefacts, documented above and in metadata.
- No TLS termination, no persistent auth store, no distributed rate limiting — these belong to the deployment layer. `API_KEY` is a single shared key for basic gating only.
- `datasets/raw/kidney_download` is a leftover download archive (gitignored going forward); the tracked `datasets/raw/*.csv` are the real inputs.
